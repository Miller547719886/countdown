# 截取面板空格切换截图保存设计

## 意图

在「截下一件事」面板已经打开并获得键盘焦点时，让用户用空格快速切换“保存截图”，减少鼠标移动；输入框和其他表单控件正在聚焦时保持原有键盘行为。

## 目标与范围

- 仅响应截取面板收到的纯空格按键，不改变现有 `cmd+1` 全局快捷键。
- 面板是 key window、且第一响应者不是输入框或其他 `NSControl`（包括其子视图）时，切换 SwiftUI 的 `saveScreenshot` 状态。
- 被表单控件聚焦时不拦截空格，由原控件继续处理。
- 将“当前焦点是否允许快捷切换”的判断抽成可单元测试的纯逻辑。

## 非目标

- 不新增全局空格快捷键，不在面板未聚焦时响应。
- 不改变截图采集、取消、重试、保存和 `cmd+return` 行为。
- 不改变面板视觉布局或现有 Toggle 的点击/辅助功能行为。

## 方案

1. **专用 `NSPanel` 子类（采用）**：在面板的 `keyDown(with:)` 中判断空格、key window 和第一响应者；符合条件时调用切换回调，否则调用 `super`。焦点判断沿第一响应者的父视图链排除输入框和其他 `NSControl`，覆盖 SwiftUI 承载的原生控件。
2. **SwiftUI `.onKeyPress`**：实现短，但只可靠覆盖已声明的 `@FocusState` 字段，难以识别所有 AppKit 表单控件，也可能抢先触发控件默认行为。
3. **`NSEvent` 本地监听器**：能集中处理事件，但需要随面板生命周期维护监听器，和系统事件传播的边界更复杂。

用户已选择方案 1。

## 交互设计

面板打开并聚焦时：

- 普通面板内容或面板本身聚焦：按空格在“保存截图”选中/未选中之间切换。
- 事项文本框、日期/时间输入框、Picker、按钮、Toggle 等表单控件（或其子视图）聚焦：空格交给当前控件处理，不切换“保存截图”。
- 面板不是 key window 时不处理空格。

## 技术约束

- 沿用现有 SwiftUI、AppKit 和 Swift Package 工具链，不新增依赖。
- `NSPanel` 子类只负责键盘事件过滤，通过闭包回调视图状态变更；面板创建仍集中在 `AppCoordinator`。
- 单元测试覆盖：允许切换的普通焦点、输入框/表单控件焦点、带修饰键或非空格按键、非 key window。
