# 截止时间编辑器设计

## 意图

让截点面板里的截止时间既能快速选日期，又能精确编辑时间。截图选项默认打开，以满足用户在截取内容时同时保留当前屏幕上下文的需求。

## 目标

- 打开截取面板时，“保存截图”默认选中并立即生成预览；权限/捕获失败仍允许取消勾选后保存事项。
- “截止时间”下提供两个 tab：快捷设置与日历设置。
- 快捷设置左侧显示本周一至日、下周一至日，右侧只提供可编辑的时间控件，默认 08:00:00，不提供时间快捷按钮。
- 日历设置左侧显示按月的日历，右侧显示时、分、秒编辑控件。
- 两个 tab 共用同一个 `Date` 状态，切换 tab、选日期、改时间都不会丢失另一部分值。
- 保留现有必填、过去时间提示、保存按钮禁用和截图错误恢复行为。

## 非目标

- 不改变 `CaptureItem` 持久化格式、通知逻辑或主窗口展示。
- 不新增第三方依赖，不改变现有纸张/墨色/朱砂视觉系统。
- 不在本轮替换系统日历或实现多月连续浏览以外的日历功能。

## 约束

- 原生 macOS SwiftUI，最低 macOS 14。
- 日期选项使用当前用户日历与本地化星期名称。
- 时间编辑至少支持时、分、秒；快捷 tab 与日历 tab 的时间编辑行为保持一致。
- 默认截图捕获沿用现有 ScreenCaptureKit 权限错误与重试路径，不自动修改系统设置。

## 方案比较

1. **两套独立表单**：快捷 tab 和日历 tab 各自维护日期、时间状态。实现直观，但切换 tab 容易出现状态分叉，保存逻辑也会重复。
2. **共用 `Date` 的双视图编辑器（采用）**：使用一个截止时间 `Date`，快捷 tab 只负责日期快捷按钮和时间控件，日历 tab 负责日历选日和同一组时间控件。状态同步天然一致，改动集中在 `CapturePanelView.swift`。
3. **完全依赖系统 `DatePicker`**：日期与时间输入最原生，但无法可靠提供秒级编辑，也难以表达本周/下周 14 个日期选项。

采用方案 2，因为它满足两个视图的明确分工，同时保留原生控件的编辑习惯，并避免引入新的领域模型。

## 交互设计

- 面板进入时 `deadline` 默认为最近一个可用日期的 08:00:00；用户在任一 tab 选择/编辑后，期限即确认。
- tab 使用现有规则线与纸张色，激活态使用朱砂色文字/底线，不增加圆角卡片层级。
- 快捷 tab 的日期区按两列分组：左列“本周”，右列“下周”；每列展示周一至周日。
- 日历 tab 使用 SwiftUI `DatePicker` 的月历样式作为左侧日期视图；右侧放置可编辑时、分、秒字段。
- 默认截图开启后立即调用现有捕获服务；若失败，错误文案与“打开系统设置/重试”保留，取消勾选即可回到无截图保存。
