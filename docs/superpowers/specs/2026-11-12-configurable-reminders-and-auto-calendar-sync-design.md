# 可配置提前提醒与新建事项自动同步设计

## 意图

创建待办时即可设置一组提前提醒；提醒支持相对截止时间的规则和自定义日期时间。开启 Apple Calendar 同步后，新建事项在保存成功后自动写入所选日历。

## 目标

- 提醒次数默认 1；调整次数后，默认提醒日按 N、N-1、……、1 天排列，每条默认早上 08:00。
- 每条相对提醒可调整提前天数和时刻；选择“自定义”后显示日历日期控件及时间控件。
- 提醒计划随待办一起持久化；编辑期限后相对提醒跟随新期限，自定义提醒保持选定时刻。
- 本地通知在新建和恢复时安排，在修改时重排，在完成或删除时取消。
- Apple Calendar 同步开启且配置可用时，新建成功即自动同步；“同步现有事项”仅用于迁移已有事项。

## 非目标

- 不改变现有待办与日历事件的双向冲突规则。
- 不把本地通知授权与 Apple Calendar 授权合并，也不要求用户必须授予其中任何一项才能保存待办。
- 不改变现有日历端提醒行为；本次可配置提醒由截点的本地通知负责。

## 约束

- 使用现有 macOS 14、SwiftUI、UserNotifications、EventKit 与 JSON 持久化方案。
- 老 JSON 不含提醒字段时，沿用旧的截止时刻提醒行为。
- 用户没有通知权限时仍可创建和保存事项。
- 保持纸张、墨色、朱砂色的现有界面风格。

## 方案比较

1. **只存绝对提醒日期**：实现简单，但修改截止时间后默认的“提前 N 天”提醒不会跟随新期限。
2. **只存相对提醒规则**：适合按天数提前并随期限更新，但无法表达用户明确选中的自定义日期。
3. **相对规则与自定义日期并存（采用）**：相对规则保存提前天数与时刻，自定义模式保存绝对日期时间。默认列表按 N 到 1 天生成；期限修改时相对规则自然更新，自定义日期保留原值。

采用方案 3。日历同步沿用本地新增事项的既有同步路径，并为新建入口提供明确方法与设置说明；已有事项仍由用户显式迁移。

## 交互设计

- 提醒次数控件默认 1；0 表示不提醒，控件上限为 30 次。
- 每条提醒默认处于相对模式，天数按当前次数从 N 递减到 1，时间为 08:00。
- 相对模式下用户可调整提前天数和具体时刻；选择“自定义”后显示日期日历与时间控件。
- 自定义提醒不得晚于截止时间；无效时显示提示并禁用保存。
- 设置页说明开启同步后新建事项自动同步，旧事项通过“同步现有事项”迁移。

## 验收

- 新建事项默认产生一条截止前一天 08:00 的提醒计划。
- 次数为 3 时默认计划为截止前三天、前两天、前一天，均为 08:00；每条可单独修改。
- 自定义模式可选日历日期与时刻；老记录仍按原截止时间安排提醒。
- 新建、编辑、完成、恢复、删除会更新本地通知；同步关闭时新建不会触发 EventKit 写入，开启时保存后的新建事项自动触发同步。
- `swift build -c release` 与 `git diff --check` 通过。
