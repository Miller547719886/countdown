# 日历节假日与节气标注设计

## 意图

在截点捕获面板的月历日期格中补充中国大陆法定节假日/调休和二十四节气，帮助用户选择截止日期时快速看懂“休、班、节气”。重点是复用经过维护的上游数据与计算实现，不由本项目手写年度放假规则或节气算法。

## 目标

- 在现有月历格中显示节假日休息日、调休上班日和节气名称。
- 保留 `holiday-cn` 的按年数据与国务院公告来源，离线可查询已内置年份。
- 使用 Swift 原生的 `Tyme4Swift 1.5.0` 计算 1900—2100 范围内的节气日期。
- 通过 `JiedianCore` 提供可测试的日期标注查询，视图只负责呈现。
- 对没有已核验假期资料的年份不推算、不显示伪造的“休/班”；节气仍独立显示。

## 非目标与反目标

- 不把普通周末自动标成“法定节假日”。
- 不根据固定日期或重复模式推断未来年度的调休安排。
- 不在这次改动中新增联网更新、农历展示、节日详情页或替换系统 `DatePicker`。
- 不改变日期选择、过去日期禁用、截止时间保存等现有行为。

## 约束

- 当前项目是 Swift Package、macOS 14+，日历网格位于 `CapturePanelView`。
- 上游源码和数据均需保留 MIT 许可证、版本和来源说明。
- `holiday-cn` 当前内置 2007—2027 年年度 JSON；缺失年份必须安全返回“无安排数据”。

## 方案比较

1. **Swift 原生上游组合（采用）**：固定 vendoring `Tyme4Swift 1.5.0`，并直接内置 `NateScarlet/holiday-cn` 年度 JSON。优点是节气实现无需跨语言改写，假期字段和官方 `papers` 链接可追溯；缺点是第三方 Swift 源码体积较大。
2. **只引用 `vsme/chinese-days` 生成 JSON**：资源较小、同时覆盖节假日与节气，但发布物由 TypeScript 构建生成，Swift 端仍需维护跨语言生成/解析流程，且生成 JSON 不保留每年公告链接。
3. **运行时联网读取**：数据更新及时，但会把网络、缓存、失败重试和首次离线状态带入日期选择器，不符合当前本地优先的捕获面板。

## 设计

- 新增 `ChineseCalendarData` 核心查询层：把 `Date` 的公历年月日转换为上游 `SolarDay`，仅在节气当天返回节气名；从 `Bundle.module/Resources/Holidays` 合并年度 JSON，按日期返回 `.offDay(name:)` 或 `.makeUpWorkday(name:)`。
- 资源加载为惰性、只读、按公告年份升序合并；同一实际日期以较新的年度文件为准。资源缺失、JSON 无效或日期超出覆盖范围时返回空假期状态，不阻塞日期选择。
- 月历日期格保留现有选中态、今天标记和过去日期禁用；在日期下方增加紧凑的“休/班”和节气文本，并为 VoiceOver 提供完整日期、假期名和节气名。
- 添加小型图例说明“休/班/节气”，避免仅靠颜色理解含义。休息日沿用朱砂色，补班沿用橄榄色，节气使用低对比度墨色。
- 在 `JiedianChecks` 中覆盖 2026 年已公告休息日、补班日、节气日和未覆盖年份的安全降级；保留现有全量检查。

## 交付边界

实现完成后运行 `swift run JiedianChecks`、`swift build -c release`、`git diff --check`，并检查第三方许可证/来源文件随资源保留。年度假期数据更新仍通过后续固定上游版本的资源更新完成，不在运行时推断。
